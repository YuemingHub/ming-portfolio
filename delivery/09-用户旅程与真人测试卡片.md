## 2. 模拟旅程与真人测试的区别

| 维度 | 自动化模拟 | 真人测试 |
| --- | --- | --- |
| 执行者 | Playwright 脚本 | 真实读者 |
| 能证明 | 路径可达、控件可用、文本存在、计数一致 | 是否理解、是否信任、是否卡住、是否被误导 |
| 不能证明 | 理解、动机、情绪、真实任务完成 | 跨环境稳定性、代码回归 |
| 输出 | 通过/失败与截图 | 原话、卡点、严重度、完成率 |
| 本轮状态 | 4/4 通过（生产已上线） | 0 人执行（已排期） |

本文不提供任何“用户说……”“反馈很好”之类的引述，因为没有真人反馈可引。

6. 屏幕阅读器、真实 Safari、真实手机按 07 的专项卡执行。
7. 全部完成后，才更新状态。

## 6. 联系与交流通道（2026-11-03）

联系与合作页现在是三条公开通道，而不是一个 GitHub Issues 按钮：

| 通道 | 页面呈现 | 适合什么 |
| --- | --- | --- |
| 抖音 | 账号 `Ming`、抖音号 `YMHomeLink`、用户提供的分享卡原图 | 看更新、短视频沟通 |
| 公众号 | 用户提供的微信二维码原图，配“用微信扫一扫”说明 | 关注文章与更新 |
| 邮箱 | `mingos2026@163.com`，点击打开邮件客户端 | 合作、采访、正式沟通 |
| GitHub Issues | 保留为补充入口，放在联系面板的说明行 | 公开、可追踪的技术或合作议题 |

四条路径都不要求先填写表单，也不收集联系信息。页面上的“合作简报”仍只在浏览器本地生成，不发送、不保存。

### 6.1 模拟旅程的补充

- 机构合作方：从首页“联系与交流”进入，能看到三条通道，不需要登录；可直接复制邮箱或打开邮件客户端。
- 技术评估者：仍可从联系页的 GitHub Issues 进入公开议题。
- 家庭用户：不会被要求留电话、微信或邮箱；公众号二维码只是可扫，不强制。
- 研究 / 写作者：邮箱是正式沟通入口，GitHub Issues 用于公开记录。
